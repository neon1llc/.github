# Contributing

Use the issue forms for reproducible bugs and documentation fixes. Report security problems privately as described in [SECURITY.md](SECURITY.md). Don't put passwords, tokens, private sign-in links, or customer data in issues or pull requests.

## Propose a change

1. Read the repository README and follow its setup, branch, and check instructions.
2. Open a focused pull request with the problem, the change, and the checks you ran.
3. Keep generated files, unrelated cleanup, and credentials out of the change.
4. A maintainer reviews the change and may ask for revisions or close it when it doesn't fit the repository. The README names the checks and current status; no review or response time is promised.

## Licenses

Each repository sets its own terms. Read that repository's `LICENSE`, `LICENSE-CODE`, `NOTICE`, and `TRADEMARK.md` files where present. Code and writing can have different terms, and an organization profile summary does not grant rights to copy material between repositories. State any license conditions your contribution needs in the pull request before review.
